# 자산 시뮬레이터

부동산(아파트) · 미국주식 · 한국주식 · ISA · 연금 · 주택담보대출을 모두 반영해서
**연도별 순자산 증감을 시뮬레이션**하고, 실제 자산 기록을 남겨
**통상 상승률 / 내 목표 / 실제 성과**를 한 그래프에서 비교하는 개인용 앱입니다.

아이폰 홈 화면에 아이콘으로 설치되는 **PWA**라서 App Store 심사, 애플 개발자 계정,
맥북·Xcode 없이 바로 쓸 수 있습니다. 설치 후에는 비행기 모드에서도 열립니다.

## 1. 아이폰에 설치하기

앱을 설치하려면 먼저 이 파일들이 **https 주소**로 열려야 합니다.
(아이폰은 파일을 직접 열어서는 홈 화면 앱으로 추가할 수 없습니다.)

아래 세 방법 중 **하나만** 하면 됩니다. 위쪽일수록 간단합니다.

### 방법 A — Cloudflare Pages (비공개 저장소 그대로, 무료) ⭐ 추천

이 저장소는 **비공개(private)** 라서 GitHub Pages 무료 플랜으로는 배포되지 않습니다.
Cloudflare Pages는 비공개 저장소도 무료로 배포해 줍니다.

1. https://dash.cloudflare.com → **Workers & Pages** → **Create** → **Pages** → **Connect to Git**
2. GitHub 계정을 연결하고 `WJ-1` 저장소를 선택
3. 빌드 설정은 **전부 비워 둡니다**
   - Framework preset: `None`
   - Build command: (비움)
   - Build output directory: `/`
4. **Save and Deploy** → 1분 뒤 `https://wj-1-xxxx.pages.dev` 주소가 생깁니다
5. 그 주소를 아이폰 **Safari**에서 열고 아래 [홈 화면에 추가](#홈-화면에-추가) 진행

> Netlify(netlify.com)도 동일한 방식으로 무료·비공개 저장소를 지원합니다.

### 방법 B — GitHub Pages (저장소를 Public으로 전환)

앱 코드에는 **개인 자산 정보가 전혀 들어 있지 않습니다.**
입력한 금액·기록은 오직 아이폰 내부에만 저장되므로, 코드를 공개해도 자산 정보는 노출되지 않습니다.

1. GitHub 저장소 → **Settings** → 맨 아래 **Change repository visibility** → **Public**
2. **Settings** → **Pages** → Source: **Deploy from a branch**
3. Branch: `main` / 폴더: `/ (root)` → **Save**
4. 1~2분 뒤 `https://swj7124-netizen.github.io/WJ-1/` 주소가 열립니다
5. 아이폰 **Safari**로 접속 후 아래 [홈 화면에 추가](#홈-화면에-추가) 진행

> 이 브랜치(`claude/personal-asset-simulator-49ten9`)를 아직 `main`에 합치지 않았다면,
> Pages의 Branch 목록에서 이 브랜치를 직접 골라도 됩니다.

### 방법 C — 집 안 PC에서만 (인터넷 배포 없이)

PC와 아이폰이 같은 Wi-Fi에 있을 때만 동작합니다. 설치 후 오프라인 사용은 가능하지만,
iOS가 저장소를 비울 경우 다시 PC를 켜야 하므로 **장기 사용에는 A·B를 권장**합니다.

```bash
# 저장소 폴더에서
python3 -m http.server 8080
# 아이폰 Safari에서 http://<PC의_내부IP>:8080 접속
```

### 홈 화면에 추가

1. **Safari**로 앱 주소를 엽니다 (Chrome 앱에서는 설치되지 않습니다)
2. 하단 가운데 **공유 버튼** 을 누릅니다
3. 목록을 내려 **홈 화면에 추가** 를 선택합니다
4. 홈 화면 아이콘으로 실행하면 주소창 없는 전체화면 앱으로 열립니다

## 2. 사용법

### 입력 탭
- 자산 카드를 눌러 펼치면 **보유 종목 / 계좌 구분 / 평가금액 / 적립 계획**을 입력합니다.
- **수익률은 직접 입력하지 않습니다.** 고른 종목의 통상 장기 수익률 범위 중간값이 자동으로 적용됩니다.
  (예: 서울 아파트 → 연 4.5%, 나스닥100 2배 → 연 12.5%)
- **계좌 구분**(부동산·미국주식·한국주식·ISA·연금·암호화폐·금·현금·기타)은 색상과 자산 구성 그래프의 묶음 단위입니다.
  ISA 계좌에 나스닥 2배를 담았다면 계좌 구분은 `ISA`, 종목은 `나스닥100 2배`로 고르면 됩니다.
- 종목별로 항목을 따로 만들 수 있습니다. QLD·UPRO·DGRO·USD·SGOV·SOXL·TIGER·KODEX·ACE 등을
  각각 한 줄씩 넣어 두면 종목별 잔고와 적립액이 그대로 시뮬레이션에 반영됩니다.

#### 적립 계획

종목마다 **매 영업일 / 매주 / 매월** 중 하나를 골라 1회 매수 금액과 기간을 지정합니다.
한 종목에 여러 계획을 겹쳐 넣을 수 있어서, 시기별로 금액이 바뀌는 적립도 그대로 표현됩니다.

| 주기 | 연 환산 | 예시 |
|---|---|---|
| 매 영업일 | × 252회 | 30만 × 252 = 연 7,560만 |
| 매주 | × 52회 | 50만 × 52 = 연 2,600만 |
| 매월 | × 12회 | 200만 × 12 = 연 2,400만 |

- 시작·종료는 **연월** 단위로 지정합니다. 비워 두면 각각 "지금부터", "계속"으로 처리됩니다.
- 시작·종료가 연도 중간이면 그 해는 **겹치는 개월 수만큼 안분**됩니다.
  (예: 2026-09 시작이면 2026년은 4개월치만 반영)
- 예시 — QLD에 `매 영업일 30만 / 2026-09 ~ 2035-12` 와 `매월 200만 / 2036-01 ~ 계속` 두 계획을
  같이 넣으면, 2035년까지는 연 7,560만, 2036년부터는 연 2,400만으로 자동 전환됩니다.
- 시뮬레이션 가정의 **적립액 증가율**은 모든 계획에 매년 복리로 곱해집니다.
- 대출은 **현재 잔액 / 이자율 / 남은 상환기간 / 남은 거치기간 / 상환방식**을 넣으면
  월 단위로 상각 계산해서 매년 잔액이 줄어드는 것까지 반영합니다.
  매월 추가 상환액을 넣으면 조기 상환 효과도 볼 수 있습니다.
- **금액 단위는 모두 만원**입니다. (예: 8억 → `80000`)

### 시뮬레이션 탭
- 낙관 / 기본 / 보수 3개 시나리오와 부채 잔액을 함께 그립니다. 그래프를 손가락으로 문지르면 연도별 값이 표시됩니다.
- **명목 금액 / 실질 가치** 전환: 실질 가치는 물가상승률을 반영해 "지금 돈으로 얼마인지"로 환산합니다.
- 자산 구성 변화(스택 차트), 대출 완제 시점, 누적 이자, 연평균 성장률(CAGR), 연도별 상세 표를 제공합니다.
- 출생연도를 입력하면(데이터 탭) 표에 나이가 함께 표시됩니다.

### 기록 탭
- **목표 연도 + 목표 순자산**을 설정하면 목표까지의 경로가 그려집니다.
- **+ 오늘 기록** 을 누르면 현재 총자산·총부채가 자동으로 채워지고, 수정 후 저장하면 이력이 쌓입니다. (같은 날짜는 덮어씁니다)
- 그래프에서 **목표 경로 / 통상 전망 / 실제 기록** 세 곡선을 한눈에 비교합니다.
- 기록이 2개 이상 쌓이면 세 가지 연평균 성장률을 비교해 줍니다:

  | 지표 | 의미 |
  |---|---|
  | 실제 연환산 | 첫 기록 → 최근 기록의 실제 연평균 성장률 |
  | 목표 필요 | 목표 달성에 필요한 연평균 성장률 |
  | 통상 전망 | 입력한 통상 수익률대로 갔을 때의 연평균 성장률 |

  분기마다 한 번씩만 기록해도 몇 년 뒤에는 꽤 정확한 나만의 성장률이 나옵니다.

### 데이터 탭
- **파일로 내보내기**: 공유 시트에서 **"파일에 저장"** 을 고르면 아이폰 **파일 앱**의 원하는 폴더
  (예: iCloud Drive/자산기록)에 `자산시뮬레이터_YYYY-MM-DD.json` 이 저장됩니다.
- **파일에서 가져오기**: 백업 파일을 골라 그대로 복원합니다. 기기를 바꿔도 이력이 이어집니다.
- 테마(다크/라이트/시스템), 출생연도, 전체 초기화.

> **백업을 권장하는 이유**: 평소 데이터는 Safari의 저장소에 들어 있습니다.
> iOS는 앱을 오래 쓰지 않으면 이 저장소를 정리할 수 있으므로, 기록을 남길 때마다
> 한 번씩 파일로 내보내 두면 안전합니다.

## 3. 계산 방식

**자산** — 매년 `평가액 × (1 + 수익률) + 연간 적립액 × (1 + 수익률)^0.5`
(적립이 연중 고르게 분산된다고 보고 평균 반년치 수익을 반영).
연간 적립액은 그 해의 모든 적립 계획을 기간 겹침만큼 안분해 합산합니다.

**대출** — 월 단위 상각. 상환방식별로 다르게 계산합니다.

| 방식 | 계산 |
|---|---|
| 원리금균등 | 매월 `잔액 × i / (1 − (1+i)^−n)` (i = 월이자율, n = 남은 개월수) |
| 원금균등 | 매월 원금 = `최초잔액 / 상각개월수`, 이자는 잔액 기준 |
| 만기일시 | 만기까지 이자만, 만기에 원금 일시상환 |

거치기간 중에는 이자만 납입하고, 추가 상환액은 전액 원금에서 차감합니다.

**수익률** — 종목별 통상 장기 명목 수익률 **범위의 중간값**을 자동 적용합니다.
표에 적힌 범위의 정중앙이 곧 적용 수익률이라, 값이 어디서 왔는지 앱 안에서 바로 검증됩니다.

혼합 상품은 구성 종목의 가중평균으로 자동 계산되므로, 구성 종목 값을 바꾸면 함께 따라 움직입니다.

**레버리지 상품 수치에 대해** — 나스닥 2배가 나스닥 1배의 2배 수익률(23%)이 아닌 12.5%인 것은
일별 리밸런싱 상품의 **변동성 손실**과 **조달비용** 때문입니다. 대략 다음 관계를 따릅니다.

```
레버리지 수익률 ≈ L×기초수익률 − (L²−L)/2 × 변동성² − (L−1)×조달금리 − 보수
```

나스닥(변동성 25%)에 L=2를 넣으면 손실분이 연 6%p 안팎, 조달비용이 4%p 안팎이라
1배와 기대값이 크게 벌어지지 않습니다. 반도체는 기초 변동성이 37.5% 수준이라 손실분이 훨씬 커서,
같은 가정으로 계산하면 **2배(USD)는 8%, 3배(SOXL)는 −6%** 가 나옵니다.
3배는 배율이 오를수록 손실분이 제곱으로 커져 기대값이 음(−)으로 돌아섭니다.

**SOXL 을 −6% 로 잡은 것에 대해** — 이 값은 "30년 계속 들고 있으면"을 가정한 숫자입니다.
레버리지 ETF는 애초에 장기 보유용으로 설계된 상품이 아니라, 단기·중기 방향성 베팅 도구입니다.
SOXL 을 트레이딩 포지션으로 굴리실 생각이라면 이 항목을 **계산에서 제외**하거나
SOXX(1배, 14%)로 바꿔 두는 편이 실제에 더 가깝습니다.

다만 이건 어디까지나 기대값입니다. 레버리지는 **하락장에서 원금의 대부분을 잃을 수 있고**
(2008년 S&P500 3배는 −95%, 2022년 SOXL은 −86% 수준), 이 앱의 보수 시나리오도 그런 구간까지는
표현하지 못합니다. 비중이 크다면 표시된 숫자보다 보수적으로 보시는 편이 안전합니다.

**커버드콜에 대해** — TIGER 나스닥100 타겟데일리커버드콜은 분배율이 연 10%를 넘지만,
분배금은 수익이 아니라 상승분을 미리 나눠 주는 성격에 가깝습니다. 상승장에서 상단이 잘리므로
**총수익(NAV + 분배금) 기준으로는 나스닥100 지수보다 낮은 8%** 로 잡았습니다.

**암호화폐 수치에 대해** — 다른 자산군과 달리 코인은 기댓값을 계산할 근거 자체가 빈약합니다.
과거 CAGR(비트코인 100%+)은 초기 채택 구간의 산물이라 그대로 미래에 쓸 수 없고,
현금흐름이 없어 주식처럼 밸류에이션으로 접근할 수도 없습니다. 그래서 다음 범위의 중간값을 썼습니다.

- **하단** — 제도·기술 리스크가 현실화되어 자산군이 축소되는 시나리오
- **상단** — 채택이 계속 확산되되 규모가 커질수록 성장률은 둔화되는 시나리오

비트코인 10%, 이더리움 7.5%는 그 중간값입니다. 이더리움은 경쟁 체인 리스크가 있어 하단을 더 넓게 잡았고,
기타 알트코인은 대부분이 장기적으로 가치를 잃는다는 점을 반영해 **−2.5%** 로 두었습니다.

변동성 계수도 3.2~4.5로 가장 높게 잡혀 있어, 시나리오 폭이 ±2.5%p일 때 비트코인은 2.0~18.0%로 벌어집니다.
그래도 −80% 급락이 과거 네 차례(2011·2014·2018·2022) 있었다는 사실까지는 담지 못합니다.
**코인 비중이 커지면 이 앱의 숫자를 그대로 믿지 마세요.**

**시나리오** — 보수/낙관 조정폭(%p)에 위 변동성 계수를 곱해 적용합니다.
조정폭 ±2.5%p 라면 나스닥2배는 ±7.5%p, 서울 아파트는 ±1.75%p, SGOV는 ±0.4%p 로 움직입니다.

**실질 가치** — 명목 결과를 `(1 + 물가상승률)^경과연수` 로 나눕니다.

### 반영하지 않는 것

세금(미국주식 양도세 22%·배당세 15%·종부세·연금 인출세·가상자산 소득세), 거래비용·중개수수료,
취득세, 환율 변동, 전세보증금 변동, 소득·생활비 변화, 금리 변동, 중도 매도,
레버리지 상품의 극단적 낙폭과 상장폐지 위험, 거래소 파산·해킹 위험.
**모든 숫자는 입력한 가정에 따른 단순 추정이며 투자 권유가 아닙니다.**

## 5. 수정하기

수치 기본값은 `assets/app.js` 상단에서 바꿀 수 있습니다.

- `INSTRUMENTS` — 종목별 통상 수익률 범위(`lo`/`hi`)와 변동성 계수(`sens`).
  적용 수익률은 `(lo + hi) / 2` 로 자동 계산되므로 범위만 고치면 됩니다.
  종목을 추가하려면 항목 하나만 더 넣으면 선택 목록에 바로 나타납니다.
  `mix: [['qqq', 0.7], ['agg', 0.3]]` 형태로 혼합 상품도 만들 수 있습니다.
- `ACCOUNTS` — 계좌 구분과 색상
- `FREQ` — 적립 주기별 연 환산 횟수 (매 영업일 252 / 매주 52 / 매월 12)
- `defaultState()` — 처음 실행 시 채워지는 자산·부채·목표.
  현재 실제 보유 종목과 잔고가 들어 있습니다. 데이터 탭의 **전체 초기화**를 누르면 이 상태로 되돌아갑니다.
- 색상은 `assets/styles.css` 의 `:root` 변수(`--c-us`, `--accent` 등)

파일을 고친 뒤 커밋·푸시하면 배포가 자동으로 갱신되고,
아이폰에서 앱을 다시 열면 최신 버전이 받아집니다.
바로 반영되지 않으면 앱을 완전히 종료한 뒤 다시 실행하세요.
